# Install set for the reference CI workflows (.github/workflows/*.yml).
# A floating training environment invalidates the manifest's env digest, so CI
# always installs from this file, never from bare package names.
#
# What this file pins, and what it does not:
#
#  - The three mbt packages are pinned to the release tag v__MBT_VERSION__.
#    Reproducible AND installable straight from a fresh checkout, with no
#    private index. Note that a git TAG is movable, on GitHub included; the
#    immutable form is a commit SHA, so replace @v__MBT_VERSION__ with the SHA
#    you scaffolded from wherever that distinction matters to you.
#    The tag resolves once the matching vX.Y.Z release exists on the mbt repo -
#    its release.yml builds that tag's wheels. Until it is cut, the install
#    fails at "git checkout -q vX.Y.Z", and the SHA swap above is the stopgap.
#  - The numerics stack below is pinned exactly, at the versions the mbt install
#    that scaffolded this project was running. These decide model numerics, and
#    pinning mbt pins none of them.
#  - Their own transitive dependencies are NOT pinned, and nothing here is
#    hash-verified. That needs a real lock, which needs mbt on PyPI (a git ref
#    has no wheel hash to record). Once it is published, switch the three refs
#    to plain version pins (mbt-core==X.Y.Z) and generate the full lock:
#      uv pip compile --generate-hashes requirements.in -o requirements.txt
