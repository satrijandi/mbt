# v0.1 implementation status

The goal table from PRD §3, with evidence from this repository's test suite.

| # | Goal | Target | Status | Evidence |
|---|---|---|---|---|
| G1 | Adoption | ≥ 2 real internal models on the full PR → CI → registry loop | **Ready for dogfooding** | The loop itself is proven end-to-end on `examples/churn_demo` (3 models, 2 datasets): `tests/test_e2e_churn_demo.py`. Migrating *internal* models needs the org's data and the DS design partner - outside this repo |
| G2 | Reproducibility | `mbt build --manifest` reproduces metrics exactly (XGBoost) | **Met** | `test_full_build_reproduce_state_promote` asserts bit-identical metrics for all three models across a `--manifest` rerun; the compliance suite asserts seed determinism per adapter |
| G3 | Economy | A typical PR retrains only the modified subgraph; cost in the PR comment | **Met** | State-economy E2E: anchor drift retrains nothing; a one-model edit retrains exactly that model with its dataset cache-hit. The shipped PR bot (`scripts/pr_comment.js`) renders the retrained list + cost estimate from `run_results.json` |
| G4 | Extensibility | LightGBM adapter with zero mbt-core changes | **Met** | `mbt-lightgbm` imports only `mbt-adapter-base` (enforced by `test_no_core_imports`), passes the full compliance suite, and `tests/test_adapter_swap.py` switches a demo model by editing only the spec |
| G5 | Time-to-first-model | `mbt init` → trained, registered model < 1 hour | **Met (mechanically)** | The quickstart path runs in **under a minute** end-to-end in CI (`tests/test_cli_basics.py` + E2E). The human-timed walkthrough with the DS partner remains an organizational step |

## Known limitations (v0.1)

- Binary classification only (regression/multiclass were explicit stretch).
- Slice-level gates are evaluated and block registration; champion slice
  gates compare point deltas only (the ADR-18 bootstrap bound is whole-split).
- Artifact stores are `file://` or `s3://` (via `mbt-core[s3]`); artifact GC
  (`mbt clean --artifacts-older-than`) covers `file://` stores, object stores
  use bucket lifecycle rules.
- `mbt run-operation` renders macros; adapter-invoking operations are out of
  scope until dogfooding demands them (TSD §10.7).
- Iceberg sources, sklearn/PyTorch, Feast, and ensembles are v1
  (see `docs/roadmap.md`). Shipped post-v0.1-scope:
  `mbt-snowflake` (ADR-16: multi-table feature+label datasets,
  push-down reproducible sampling), `mbt-spark` (lakehouse data,
  spark-submit compute, distributed SparkML training; validated on
  Spark 3.5 and 4.1) and `mbt-h2o` (AutoML with MOJO artifacts; optional
  Sparkling Water, which pins Spark 3.5) per ADR-17. The mbt-snowflake
  unit tests execute the generated SQL in DuckDB; an opt-in live suite
  (`-m live_snowflake`, nightly in CI once `SNOWFLAKE_*` secrets are
  configured) additionally covers joins, sampling reproducibility,
  snapshot tokens, and a full local-training loop on a real account.
  Also shipped post-v0.1-scope: batch scoring pipelines (`scoring`
  resource + `mbt score`) with training-time baselines and PSI/KS shift
  monitors, and delayed ground-truth evaluation (`mbt monitor`) with
  realized-metric gates and a once-per-run evaluation ledger (ADR-20/21);
  the prediction sink ships for the local adapter (contract 1.1), and
  warehouse sinks are follow-ups. Online (request/response) serving
  remains a non-goal. A docker-compose showcase (`examples/showcase`,
  opt-in `-m live_showcase`) proves the loop against real services:
  MLflow over HTTP, an S3-compatible object store (SeaweedFS) as lake +
  artifact store, Sparkling Water training inside the executors of a
  standalone Spark cluster, the state-diff CI loop on Gitea + Woodpecker
  (slim PR builds, baseline republish, exit-code-classified alerts,
  protected GitOps promotion), a digest-pinned deployable unit in a Zot
  registry that reproduces its own manifest and refuses tampered
  environments (with oras provenance artifacts), Airflow scheduling of
  that unit via a git-synced deploy repo (quality verdicts never retried),
  and the tutorial's Pushgateway/Prometheus observability spec through
  build -> promote -> score -> monitor. An optional k3d + ArgoCD profile
  (separately gated, local-only) syncs the same deploy repo into CronJobs.
- OpenTelemetry spans (NFR-06 optional) are not wired yet.
- New mbt releases that add spec fields flip config hashes (full-dump
  hashing); upgrade PRs should expect a one-time full-retrain signal (ADR-7
  documents the mitigation path).
